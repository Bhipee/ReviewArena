# COMP6708 Assignment 3 — Mini Demo Proposal

## ScholarMate：面向博士生与导师的「组会论文助手」

> 一句话：把学生的论文草稿 + 课题组已有论文/组会记录变成可检索的知识库，用 **RAG + MCP + Agent Skills** 帮学生**做组会准备**、帮导师**快速审稿、提问**，每个回答都附可点击的原文出处。

---

## 1. 问题与场景（Problem Statement）

| 角色 | 痛点 | 现状 |
|---|---|---|
| 博士生 | 每周组会要整理进展、找相关工作、预判导师会问什么 | 手动翻 PDF、Google Scholar，耗时且容易漏 |
| 导师 | 同时带多名学生，读草稿的时间有限；想知道“这篇和组里之前的工作有什么区别”“有没有漏引” | 只能逐页读，组内历史知识散落在各人电脑里 |
| 通用 ChatGPT | 能总结，但**没有组内上下文**、**会编造引用**、不能实时查新论文 | 结果不可追溯，导师不敢信 |

**目标**：一个可交互的 Web 系统，回答必须**有据可查**（RAG 引用到页码），相关工作必须**真实存在**（MCP 实时调用 arXiv），常用任务**一键完成**（Agent Skills 固化流程）。全部 training-free。

---

## 2. 用到的 LLM 技术及选择理由

| 技术 | 在系统中的作用 | 为什么选它 |
|---|---|---|
| **RAG** | 课题组知识库（组内论文、学生草稿、过往组会纪要）切块 → 向量库；问答时检索 top-k 并要求带 `[文件, 页码]` 引用 | 解决“没有组内上下文”和“幻觉”；加新论文只需重新入库，不用训练 |
| **MCP** | 封装 arXiv（可选 Semantic Scholar）检索为 MCP server，LLM 以 tool call 方式调用 | 标准化工具接口，可替换/扩展数据源；查到的论文是真实的，杜绝编造引用 |
| **Agent Skills** | 3 个技能，每个是一份 `SKILL.md`（指令 + 输出模板）按需加载：<br>① `weekly-brief` 组会周报<br>② `reviewer-2` 结构化审稿意见<br>③ `related-work-gap` 漏引/新颖性检查 | 把导师和学生的固定流程写成可复用的“操作手册”，输出格式稳定；体现渐进式加载（只在用到时把技能放进上下文） |

**“大规模数据库”加分点**：知识库可预先导入某一领域的 arXiv 摘要（如 Kaggle arXiv metadata 的一个子类，几万条）作为背景库，与组内私有文档分两个 collection 检索并标注来源。

## 3. 系统架构

```
 ┌────────────── Streamlit / Gradio UI ──────────────┐
 │ [上传 PDF]  [对话框]  [技能按钮×3]  [引用侧栏/原文高亮] │
 └──────────────────────┬────────────────────────────┘
                        │
               Agent 编排层 (LLM + tool calling)
          ┌─────────────┼──────────────────┐
          ▼             ▼                  ▼
   RAG 检索工具     MCP Client          Skill Loader
  (Chroma/FAISS     ↔ arXiv MCP Server   (skills/*.md 按需注入)
   + bge 嵌入)
          │
   知识库：组内论文 / 学生草稿 / 组会纪要 / arXiv 摘要子集
```

**技术栈（全部现成，两天可完成）**
- LLM：任一支持 tool calling 的 API（Claude / GPT / Qwen / DeepSeek，组里有哪个用哪个）
- 嵌入与向量库：`bge-small` 或 API embedding + Chroma（本地文件，免部署）
- PDF 解析：PyMuPDF（保留页码，用于引用定位）
- MCP：Python `mcp` SDK 写一个 ~50 行的 arXiv server（`search_papers`, `get_abstract`），或直接用社区现成的 arxiv MCP server
- UI：Streamlit（`st.chat_message` + 侧边栏引用卡片）

## 4. 5 分钟现场演示脚本

| 时间 | 操作（现场点 UI） | 想让观众看到什么 |
|---|---|---|
| 0:00–0:40 | 1 张幻灯片：场景 + 架构图 | 问题是什么、用了哪三种技术 |
| 0:40–1:40 | **学生视角**：上传一篇论文草稿 PDF，问“我的方法和组里 2024 年那篇 X 有什么区别？” | 回答带 `[X.pdf p.4]` 引用，点击侧栏显示原文段落 → **RAG 可追溯** |
| 1:40–2:40 | 点 **Related-work Gap** 按钮 | 界面显示 tool call 日志：`arxiv.search_papers(...)` → 列出 3 篇真实近期论文 + “草稿未引用” 标记 → **MCP** |
| 2:40–3:40 | **导师视角**：点 **Reviewer #2** 按钮 | 输出结构化审稿意见（贡献/弱点/必问问题），每条带证据页码 → **Agent Skill** |
| 3:40–4:20 | 点 **Weekly Brief** | 生成一页组会简报（本周进展、问题、下周计划、导师可能问的 3 个问题），可下载 Markdown |
| 4:20–5:00 | 1 张幻灯片：小评测结果 + 影响 + 局限 | 见第 5 节 |

> 演示建议：提前把知识库建好、把问题预置成快捷按钮；同时录一段完整操作视频作为断网/接口挂掉时的备份。

## 5. 评测（小而真实，加分用）

- 构造 **20 个问答对**（来自组内 3–5 篇论文，人工写标准答案与出处页码）。
- 对比 **纯 LLM vs. ScholarMate**：
  - 答案正确率（人工打分）
  - **引用准确率**（引用的页码是否真的包含依据）
  - **相关工作真实性**（纯 LLM 推荐的论文有几篇查不到 vs. MCP 返回 100% 真实）
- 一张柱状图放在最后一页幻灯片即可。

## 6. 四人分工

| 成员 | 角色 | 具体任务 | 交付物 |
|---|---|---|---|
| **A** | RAG / 知识库负责人 | PDF 解析（带页码）、切块、嵌入、Chroma 入库；检索函数 `retrieve(query, k)` 返回带出处的片段；准备演示用的组内论文与草稿 | `rag.py`、建好的向量库、演示数据集 |
| **B** | MCP + Agent 负责人 | 写 arXiv MCP server；LLM tool-calling 编排循环（RAG 工具 + MCP 工具）；写 3 个 `SKILL.md` 和加载逻辑 | `mcp_arxiv_server.py`、`agent.py`、`skills/` |
| **C** | UI / 集成负责人 | Streamlit 界面：上传、对话、技能按钮、引用侧栏、tool call 日志展示、简报下载；整合 A、B 的接口；负责演示机环境 | `app.py`、可一键启动的 `run.sh`、备份录屏 |
| **D** | 评测 + 幻灯片 + 主讲 | 写 20 题评测集并跑对比实验；做 5–6 页幻灯片（场景、架构、技术理由、评测图、影响/局限）；写并排练演示台词，现场主讲（C 操作） | 评测表与图、`Assignment3-GroupX.pptx`、演示台词 |

**接口约定（第一天上午先定好，避免互相等待）**
- `retrieve(query: str, k=5) -> list[{text, source, page, score}]`（A → B）
- `run_agent(messages, skill: str|None) -> {answer, citations, tool_logs}`（B → C）

## 8. 风险与对策

| 风险 | 对策 |
|---|---|
| 现场网络/API 不稳定 | 准备离线录屏；LLM 设置超时重试；arXiv 结果加本地缓存 |
| 回答慢超时 | 预先建库；流式输出；限制 top-k 和输出长度 |
| 幻觉引用 | 提示词强制“只能引用检索到的片段”，UI 中无出处的句子标灰 |
| 时间不够 | 最小可行版本 = RAG 问答 + 1 个 Skill（Reviewer #2）+ arXiv MCP；Weekly Brief 和评测作为可选加分项 |

---

## 9. 预期影响

- **学生**：组会准备时间从约 1–2 小时降到 10 分钟；提前发现漏引。
- **导师**：几分钟内拿到带证据的审稿要点和提问清单，带多个学生时尤其有用。
- **课题组**：组会纪要和历史论文沉淀为可检索的“组内记忆”，新生上手更快。
- **可扩展**：加数据源只需新增 MCP server（如 Google Scholar、实验室 Wiki、Overleaf），加流程只需新增 SKILL.md，无需训练。
